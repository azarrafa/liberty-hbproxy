* RACF (and CICS) prerequisites for hbproxy. TEMPLATE: replace every <PLACEHOLDER>, review with your security administrator, run as a RACF administrator.
* Derived from the commands used on the reference LPAR (see ../../docs/racf-changes.md and ../../config/s6-remove-privileged.md there).
* <REGION_USERID> = the user ID the CICS region runs under (STARTED profile). <SERVICE_ID> = the RACF ID a caller is mapped to.

* ---- 1. Identity mapping: token "sub" claim -> RACF ID (one MAP per caller; use a dedicated service ID, not a person) -------------------
SETROPTS CLASSACT(IDIDMAP) RACLIST(IDIDMAP)
RACMAP ID(<SERVICE_ID>) MAP USERDIDFILTER(NAME('<sub claim of the caller token>')) REGISTRY(NAME('*')) WITHLABEL('<label>')
SETROPTS RACLIST(IDIDMAP) REFRESH
RACMAP ID(<SERVICE_ID>) LISTMAP
* With the OIDC client (resource-server) setup, registry is '*'. Anyone holding a token with that sub reaches <SERVICE_ID>.

* ---- 2. PassTicket: application name = the region APPLID, and the right to generate tickets ---------------------------------------------
* The PTKTDATA profile for the APPLID with a secured sign-on key (the key is a secret: generate it, never put it in a document).
SETROPTS CLASSACT(PTKTDATA) RACLIST(PTKTDATA)
RDEFINE PTKTDATA <CICS_APPLID> SSIGNON(KEYMASKED(<64 hex digits, generated by you>)) UACC(NONE)
* The region user ID generates the ticket (R_ticketserv). One profile per service ID, UACC NONE, no generic permit:
RDEFINE PTKTDATA IRRPTAUTH.<CICS_APPLID>.<SERVICE_ID> UACC(NONE)
PERMIT IRRPTAUTH.<CICS_APPLID>.<SERVICE_ID> CLASS(PTKTDATA) ID(<REGION_USERID>) ACCESS(UPDATE)
SETROPTS RACLIST(PTKTDATA) REFRESH
* Do NOT run the region as PRIVILEGED in the STARTED class: it skips these checks and lets a compromised Liberty ticket ANY ID.
*   RLIST STARTED <region job>.* ALL STDATA     want PRIVILEGED=NO. Fix: RALTER STARTED <profile> STDATA(USER(<REGION_USERID>) PRIVILEGED(NO) TRUSTED(NO))

* ---- 3. Liberty z/OS services (angel, SAF credentials) -----------------------------------------------------------------------------------
* Angel started task and its profiles (names per your angel PROC and Liberty server prefix):
*   STARTED  <ANGEL_PROC>.*   STDATA(USER(<REGION_USERID>))
*   SERVER   BBG.ANGEL                 READ for <REGION_USERID>
*   SERVER   BBG.ANGEL.<ANGEL_NAME>    READ for <REGION_USERID>
*   SERVER   BBG.AUTHMOD.BBGZSAFM.*    READ for <REGION_USERID>   (SAFCRED and the other authorized modules)
* Liberty server prefix profile (needed for SAF credentials of the mapped user; found by a 403 / CWWKS2909E without it):
RDEFINE SERVER BBG.SECPFX.BBGZDFLT UACC(NONE)
PERMIT BBG.SECPFX.BBGZDFLT CLASS(SERVER) ID(<REGION_USERID>) ACCESS(READ)
SETROPTS RACLIST(SERVER) REFRESH
* ICSF services System SSL uses (only needed once the region is not PRIVILEGED, for TLS 1.3 to HB.js; without them TLS 1.2 still works):
PERMIT CSFPKD CLASS(CSFSERV) ID(<REGION_USERID>) ACCESS(READ)
PERMIT CSFOWH CLASS(CSFSERV) ID(<REGION_USERID>) ACCESS(READ)
SETROPTS RACLIST(CSFSERV) REFRESH

* ---- 4. Key ring of the region user (server certificate + CAs that signed the HB.js and the token issuer certificates) -----------------
* Exists already on most sites. Check:  RACDCERT ID(<REGION_USERID>) LISTRING(<KEYRING>)
* It must hold: a PERSONAL (server) certificate, and the CA certificates needed to trust the HB.js server certificate and the OIDC
* issuer's JWKS endpoint (CERTAUTH).

* ---- 5. The service ID must be allowed to run the HB.js transaction (CICS) ----------------------------------------------------------
* HB.js runs the request under the PassTicket's user: <SERVICE_ID> needs CICS transaction security for the HB.js transaction (CWXN by
* default) and for whatever the HB.js scripts call.
